# volga_it_qa

Проект UI-автотестов для соревнования Volga IT 2026. Проверяются страницы Calendars, Modals, Ads и Form Fields
сайта [practice-automation.com](https://practice-automation.com/). Используется Page Object Model: действия и локаторы
находятся в `pages/`, сценарии и проверки — в `tests/`. Результаты запуска сохраняются для отчёта Allure.

Выполнил: Шульга Иван

## Требования и ограничения

- **Python 3.12+** по заданию соревнования. Версию интерпретатора выбирают отдельно:
  `requirements.txt` не устанавливает Python и не гарантирует совместимость всех будущих версий.
- **Google Chrome или Mozilla Firefox**. По умолчанию — Chrome. Другие браузеры текущая фикстура не поддерживает.
  Браузеры и драйверы не закреплены по версиям; драйвер должен соответствовать установленному браузеру. Selenium Manager
  подбирает драйвер автоматически; для скачивания нужен доступ к сети.
- **Стабильное интернет-соединение** и доступ к `https://practice-automation.com/` (**ОЧЕНЬ ВАЖНО**, у меня проваливались тесты из-за проблем с интернетом). Сетевые задержки и недоступность
  сервера могут вызывать ошибки загрузки и отправки форм. Высокая скорость соединения сама по себе не гарантирует
  доступность сайта.
- **Allure CLI** устанавливается отдельно для генерации и просмотра HTML-отчётов. Python-пакеты Allure сохраняют данные
  запуска, но не заменяют CLI.
- Для сценариев Ads блокировщик рекламы должен быть выключен.

Прямые зависимости из `requirements.txt`:

| Пакет                   | Версия   | Назначение                                                                     |
|-------------------------|----------|--------------------------------------------------------------------------------|
| `pytest`                | `9.1.1`  | Запуск тестов и фикстуры                                                       |
| `selenium`              | `4.51.0` | Управление браузером                                                           |
| `allure-pytest`         | `2.16.0` | Интеграция pytest с Allure                                                     |
| `allure-python-commons` | `2.16.0` | API `allure`: шаги, названия и вложения                                        |

Версии прямых зависимостей закреплены через `==`. 
Текущие настройки:

| Параметр                        | Значение                             | Источник                                                       |
|---------------------------------|--------------------------------------|----------------------------------------------------------------|
| Таймаут навигации               | 45 секунд                            | `config/settings.py`, `PAGE_LOAD`                              |
| Ожидание элементов по умолчанию | 10 секунд                            | `config/settings.py`, `DEFAULT`                                |
| Стратегия загрузки              | `eager`                              | `tests/conftest.py`                                            |
| Размер окна                     | 1920 × 1080                          | `tests/conftest.py`                                            |
| Изоляция                        | Новая сессия браузера на каждый тест | Фикстура `driver`                                              |
| Базовый URL                     | `https://practice-automation.com`    | Переменная окружения `BASE_URL`, читается при импорте настроек |

`eager` ожидает готовности DOM; страницы дополнительно ожидают свои элементы и результаты действий.
При таймауте навигации или распознанной ошибке соединения открытие страницы повторяется
один раз через 3 секунды. Причина первой ошибки сохраняется в Allure; повторная ошибка
завершает тест. Таймаут 45 секунд действует на каждую попытку.
`window.stop()`, повтор отправки формы и автоматический перезапуск всего теста не используются.
Сводка Form Modal после отправки ожидается до 30 секунд; 
Если Submit находится за пределами окна, прокручивается подложка модального окна;
обычный клик выполняется после проверки стабильного положения кнопки и отсутствия
перекрытия точки клика.

## Быстрый запуск

1. Клонировать репозиторий и перейти в его каталог:

   ```bash
   git clone https://github.com/sqtwix/volga_it_qa.git
   cd volga_it_qa
   ```

2. Создать виртуальное окружение:

   ```bash
   python -m venv .venv
   ```

   Активировать его в **PowerShell**:

   ```powershell
   .\.venv\Scripts\Activate.ps1
   ```

   Или в **Git Bash на Windows**:

   ```bash
   source .venv/Scripts/activate
   ```

3. Установить зависимости и запустить тесты в Chrome:

   ```bash
   python -m pip install -r requirements.txt
   python -m pytest
   ```

## Параметры запуска

| Параметр                                 | Назначение                        | По умолчанию     |
|------------------------------------------|-----------------------------------|------------------|
| `--browser=chrome` / `--browser=firefox` | Выбор браузера                    | `chrome`         |
| `--headless`                             | Запуск браузера без видимого окна | Выключен         |
| `--alluredir=ПУТЬ`                       | Каталог данных Allure             | `allure-results` |

Примеры:

```bash
python -m pytest --browser=firefox
python -m pytest --browser=chrome --headless
python -m pytest --browser=firefox --headless --alluredir=allure-results/firefox
```

Проверить только сбор тестов, сохранив имеющиеся результаты Allure:

```bash
python -m pytest --collect-only -q -o addopts=
```

## Отчёт Allure

В `pytest.ini` включены `--alluredir=allure-results --clean-alluredir`. Каждый запуск автоматически сохраняет результаты
и очищает выбранный каталог перед записью новых данных. Это относится и к запуску одного теста.

После обычного `python -m pytest` открыть временный отчёт:

```bash
allure serve allure-results
```

Или сохранить HTML-отчёт и открыть его:

```bash
allure generate allure-results --clean -o allure-report
allure open allure-report
```

Если использовался `--alluredir=allure-results/firefox`, команды должны читать именно этот каталог:

```bash
allure generate allure-results/firefox --clean -o allure-report/firefox
allure open allure-report/firefox
```

`--clean-alluredir` очищает данные тестов, а `allure generate --clean` перезаписывает HTML-отчёт. Обычный запуск с
каталогом `allure-results` удалит и его вложенные результаты, включая `firefox/`. Для хранения независимых запусков
выбирайте непересекающиеся каталоги, например `allure-results/chrome` и `allure-results/firefox`, и не запускайте между
ними очистку родительского `allure-results`.

При падении теста или его подготовки прикладывается скриншот, если сессия браузера уже создана и ещё доступна.
Результаты, шаги и вложения смотрите в Allure; каталоги `allure-results/`, `allure-report/` и `tmp/` исключены из Git.
Для остановки сервера просмотра нажмите `Ctrl+C`.

## Структура проекта

```text
volga_it_qa/
├── config/
│   └── settings.py            # URL тестируемых страниц и таймауты
├── pages/
│   ├── base_page.py           # Общие методы взаимодействия с браузером и ожидания
│   ├── ads_page.py            # Работа со страницей рекламы
│   ├── calendar_page.py       # Работа с календарём и полем даты
│   ├── form_fields_page.py    # Получение Automation Tools и заполнение Message
│   └── modals_page.py         # Работа с Simple Modal и Form Modal
├── tests/
│   ├── conftest.py            # Фикстура браузера, параметры запуска и скриншоты ошибок
│   ├── test_ads.py            # Проверки рекламного окна
│   ├── test_calendar.py       # Проверки выбора, ввода и валидации даты
│   ├── test_form_fields.py    # Проверка заполнения Message списком инструментов
│   └── test_modals.py         # Проверки модальных окон и формы
├── docs/
│   └── Полуфинал.-Автоматизация-тестирования-Java-Python.pdf
├── .gitignore                # Исключения для Git
├── pytest.ini                # Настройки pytest и сохранения результатов Allure
├── requirements.txt          # Зависимости Python с фиксированными версиями
└── README.md                 # Описание проекта и инструкции запуска
```

В проекте используется **Page Object Model**: локаторы и действия со страницами находятся в `pages/`, а сценарии и
проверки ожидаемых результатов — в `tests/`. Классы страниц наследуют общие методы из `BasePage`. Настройки URL и
ожиданий вынесены в `config/settings.py`.

При запуске тестов создаётся каталог `allure-results/` с результатами, шагами и вложениямпшеи. При генерации HTML-отчёта
создаётся `allure-report/`. Оба каталога содержат сгенерированные файлы и исключены из Git через `.gitignore`.

## Ограничения проверок

- **Submit в Form Modal / Firefox:** после `ElementNotInteractableException`
  разрешён JavaScript-клик с отдельным шагом Allure. Это проверяет обработку программного клика, но не доказывает
  доступность кнопки для обычного клика. Остальные действия используют строгий обычный клик.
- **ADS-09:** если за 6 секунд URL не стал содержать `youtube.com`, текущая реализация допускает успех при наличии двух
  вкладок. Это согласованный вариант для сети без доступа к YouTube.
- **ADS-10:** читается настройка задержки `4500` мс из DOM, а не измеряется фактическое время появления рекламы. ADS-01
  проверяет появление в течение 8 секунд.
