# volga_it_qa
Проект для международного соревнования Volga IT (2026)

## Краткое описание
**volga_it_qa** - проект для автоматизированного тестирования сайта https://practice-automation.com, 
а именно страниц календаря, модального окна, рекламы, форм. 

Использован паттерн **Page Object Model** для более структурированного и когнетивно понятного кода.

По итогу тестирования сайтов формируеться **allure отчёт**.

Стек:
- Язык программирование: python (3.12 и выше)
- библиотеки и фреймворки: selenium, pytest, allure-pytest

## Требования и ограничения

Язык проекта — **Python 3.12 и выше**, согласно заданию соревнования.
Версия интерпретатора не закрепляется в `requirements.txt`: её необходимо
выбрать отдельно при создании виртуального окружения. Совместимость каждой
новой версии Python с проектом нужно проверять запуском тестов.

Прямые зависимости закреплены в `requirements.txt` оператором `==`:

| Пакет | Требуемая версия | Назначение |
| --- | --- | --- |
| `pytest` | `9.1.1` | Запуск тестов и работа с фикстурами |
| `selenium` | `4.51.0` | Управление браузером |
| `allure-pytest` | `2.16.0` | Интеграция pytest с Allure |
| `allure-python-commons` | `2.16.0` | API `allure`: шаги, названия и вложения |
| `python-dotenv` | `1.2.4` | Средства загрузки переменных окружения из `.env` |

Устанавливайте зависимости командой `python -m pip install -r requirements.txt`.
Указанные версии должны совпадать с установленными; версии `allure-pytest`
и `allure-python-commons` в проекте согласованы между собой. Транзитивные
зависимости отдельно не закреплены, поэтому файл не является полным lock-файлом.

Поддерживаются **Google Chrome** и **Mozilla Firefox**. По умолчанию используется
Chrome; другие браузеры текущей фикстурой не поддерживаются. Точные версии
браузеров и драйверов в проекте не закреплены: по заданию нужны актуальные
версии драйверов, совместимые с установленным браузером. Браузер устанавливается
отдельно от Python-пакетов; Selenium Manager может подобрать драйвер автоматически,
для его первоначального скачивания требуется доступ к сети.

Для генерации и просмотра HTML-отчётов требуется отдельно установленный
**Allure CLI**. Пакеты `allure-pytest` и `allure-python-commons` его не заменяют.
Версии Allure CLI и необходимой ему среды выполнения в `requirements.txt`
не закреплены.

## Инструкция по быстрому запуску

1. скачивания репозитория и переход в корень:

```bash
git clone https://github.com/sqtwix/volga_it_qa.git && cd volga_it_qa
```

2. установка зависимостей:

```bash
pip install -r requirements.txt
```

3. запуск тестов в корне проекта (по дефолту браузер - chrome):

```bash
python -m pytest
```

4. Запуск локального сервера с аллюр отчётом:

```bash
allure serve <ваша папка с аллюр данными> 
allure serve allure-results/ # пример с папкой allure-results/
```

5. Сохранение отчета

```bash
allure generate allure-results/firefox --clean -o allure-report/firefox
allure open allure-report/firefox
```

## Возможности запуска

тесты можно запустить на браузере firefox и chrome (по дефолту) благодаря параметру ```--browser=<browser>```

- бразуер firefox:

```bash
python -m pytest --browser=firefox
```

- бразуер chrome:

```bash
python -m pytest --browser=chrome
```

Можно использовать параметр ```--headless``` - тогда не будет отображаться окно браузера

```bash
python -m pytest --browser=firefox --headless
```

Можно использовать параметр ```alluredir``` для указания директории сохранения отчёта:

```bash
python -m pytest --browser=firefox --alluredir=allure-results/firefox
```

Пример команды со свеми параметрами:

```bash
python -m pytest --browser=firefox --alluredir=allure-results/firefox --headless
```

## Тестовые сценарии

Каждая проверка запускается в отдельной сессии выбранного браузера. Перед
выполнением шагов открывается соответствующая страница и ожидается её готовность.
Для рекламы блокировщик рекламы должен быть выключен. Даты текущего, следующего
и предыдущего месяца вычисляются на момент запуска теста.

Ниже описаны все **45 проверок** с учётом параметризации:

| Страница | Позитивные | Негативные | Всего |
| --- | ---: | ---: | ---: |
| Calendars | 9 | 4 | 13 |
| Modals | 10 | 7 | 17 |
| Ads | 9 | 5 | 14 |
| Form Fields | 1 | 0 | 1 |

### Ads — `/ads/`

Реализация: `tests/test_ads.py`. Перед действиями с рекламой тест ожидает
появления окна; превышение таймаута завершает проверку ошибкой.
ADS-10 читает настройку таймера из DOM, а ADS-01 проверяет фактическое появление окна.

| ID | Тип | Шаги и данные | Ожидаемый результат |
| --- | --- | --- | --- |
| ADS-01 | Позитивный | Открыть страницу; дождаться рекламы не более 8 секунд. | Рекламное окно появляется. |
| ADS-02 | Позитивный | Дождаться рекламы; прочитать заголовок и текст. | Заголовок равен `Hi`, текст равен `I am an ad.`. |
| ADS-03 | Позитивный | Дождаться рекламы; нажать крестик. | Рекламная подложка скрывается. |
| ADS-04 | Позитивный | Дождаться рекламы; отправить Enter кнопке закрытия. | Рекламная подложка скрывается. |
| ADS-05 | Позитивный | Дождаться рекламы; в течение 2 секунд не закрывать её. | Окно не закрывается автоматически и остаётся видимым. |
| ADS-06 | Позитивный | Прочитать навигационную цепочку страницы. | Текст содержит `Home` и `Ads`. |
| ADS-07 | Позитивный | Прочитать основной текст страницы. | Присутствует `An ad will appear in 5…4…3…2…1`. |
| ADS-08 | Позитивный | Прочитать основной текст страницы. | Присутствует `Please make sure that ad blockers are turned off`. |
| ADS-09 | Позитивный | Дождаться рекламы; закрыть её; нажать ссылку видеоурока; переключиться в новую вкладку; после проверки закрыть её и вернуться. | URL содержит `youtube.com`; при таймауте текущая реализация допускает успех при наличии двух вкладок. |
| ADS-10 | Негативный / конфигурационный | Прочитать настройку задержки автоматического открытия из `data-popmake`. | Задержка равна `4500` мс. |
| ADS-11 | Негативный | Дождаться рекламы; попытаться нажать ссылку видеоурока под подложкой. | Клик блокируется с `ElementClickInterceptedException`. |
| ADS-12 | Негативный | Дождаться рекламы; кликнуть по тексту внутри неё. | Окно не закрывается в течение 1,5 секунды и остаётся видимым. |
| ADS-13 | Негативный | Дождаться рекламы; нажать Escape. | Подложка не скрывается в течение 1,5 секунды. |
| ADS-14 | Негативный | Дождаться рекламы; кликнуть по подложке вне окна. | Подложка не скрывается в течение 1,5 секунды. |

**Ограничение ADS-09:** из-за недоступности YouTube в используемой пользователем
сети сохранена проверка открытия вкладки как запасной вариант. Этот вариант
не подтверждает загрузку видео или доступность сервиса; вкладка может остаться
на `about:blank`.

## Структура проекта

```text
volga_it_qa/
├── config/
│   └── settings.py            # URL тестируемых страниц и таймауты
├── pages/
│   ├── base_page.py           # Общие методы взаимодействия с браузером и ожидания
│   ├── ads_page.py            # Работа со страницей рекламы
│   ├── calendar_page.py       # Работа с календарём и полем даты
│   ├── form_fields_page.py    # Получение Automation Tools и заполнение Message
│   └── modals_page.py         # Работа с Simple Modal и Form Modal
├── tests/
│   ├── conftest.py            # Фикстура браузера, параметры запуска и скриншоты ошибок
│   ├── test_ads.py            # Проверки рекламного окна
│   ├── test_calendar.py       # Проверки выбора, ввода и валидации даты
│   ├── test_form_fields.py    # Проверка заполнения Message списком инструментов
│   └── test_modals.py         # Проверки модальных окон и формы
├── docs/
│   └── Полуфинал.-Автоматизация-тестирования-Java-Python.pdf
├── .gitignore                # Исключения для Git
├── pytest.ini                # Настройки pytest и сохранения результатов Allure
├── requirements.txt          # Зависимости Python с фиксированными версиями
└── README.md                 # Описание проекта и инструкции запуска
```

В проекте используется **Page Object Model**: локаторы и действия со страницами
находятся в `pages/`, а сценарии и проверки ожидаемых результатов — в `tests/`.
Классы страниц наследуют общие методы из `BasePage`. Настройки URL и ожиданий
вынесены в `config/settings.py`.

При запуске тестов создаётся каталог `allure-results/` с результатами, шагами
и вложениями. При генерации HTML-отчёта создаётся `allure-report/`. Оба каталога
содержат сгенерированные файлы и исключены из Git через `.gitignore`.
